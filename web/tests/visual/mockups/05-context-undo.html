05 · Context menus and the undo line (V2-6)

V2-6 (needs 68, 69). Context menus on tree rows, tabs, chat messages, Files rows and board cards; every item is an existing ⌘K command with its binding shown. Reversible actions run at once and offer Undo for 10 s (also ⌘Z outside terminal and composer); irreversible ones (worktree remove with work, full quit, remove account) get a confirm naming what is lost. Three different interaction models below; all in Nunchiro Light inside the R8 window. Undo never covers content or moves anything under the pointer (needs 26, 49).

Recommendation: Option A. One menu component that matches macOS habit and maps 1:1 to palette commands (acceptance 2 drift test), plus Undo in the always-present status line, which never covers or shifts content. Borrow from B if the owner wants: keep the closed tab’s slot as a ghost for 10 s so the tab row never jumps under the pointer. Evidence: needs 26, 49, spec V2-6; main risk: the status-line undo is easy to miss for the tree, so ⌘Z must work everywhere outside the terminal and composer.

Right-click, ⇧F10 or the menu key opens it at the row. ↑↓ move, ↵ runs, letters jump, esc returns focus to the row.
Undo in the status line: replaces nothing, 10 s, one at a time; a newer action replaces it.

Interaction modelSpatial: a menu anchored to the right-clicked thing; result feedback in a fixed bar.

RationaleThe macOS habit: right-click where you are, see every command with its key, learn the key for next time (“buttons first, keys once familiar”). Undo sits in the 22 px status line that is always there, so nothing appears over content.

Trade-offStatus line is far from the tree/tab you acted on; a fast user may miss the 10 s window. Only the last action is undoable from the line (⌘Z history is not shown).

Accessibilityrole=menu / menuitem, opened by right-click, ⇧F10 or the menu key; arrow keys, type-ahead, esc returns focus to the invoking row; destructive items in red and named with “…” for a confirm; undo announced by an aria-live=polite region; countdown pauses while hovered or focused (WCAG 2.2.1).

Right-click = ⌘K scoped to the thing. Type to filter; the full command list is one ⌫ away.
Ghost tab: the closed tab keeps its slot for 10 s with Undo, then collapses. Nothing to its right moves while you might click.

Interaction modelCommand-first: right-click is a shortcut into the palette; undo is in-place.

RationaleOne surface for every action: the palette people already use, now scoped. Undo appears exactly where the removed thing was, so you see what you can bring back and no element shifts for 10 s.

Trade-offPalette opens at the top, far from a pointer at the bottom of the screen; mouse users lose the ‘menu at my cursor’ feel. Ghosts hold space for 10 s (tabs, rows, cards), which looks busy after bulk actions.

AccessibilityPalette is a role=dialog with a combobox + listbox (aria-activedescendant); the scope chip is part of the input’s accessible name; esc returns focus to the message. Ghosts are real buttons “Undo close lumen-api”; announced via aria-live.
