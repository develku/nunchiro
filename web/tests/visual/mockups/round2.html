02대화 안에서 에이전트 바꾸기

무엇을 정하나요: 한 탭에서 Claude ↔ Codex(나중에 ACP 에이전트)로 넘기는 손잡이를 어디에, 어떤 모양으로 둘지.

"채팅 / 터미널" 버튼은 무엇이었나: v1b부터 모든 세션 탭에 있는 보기 전환입니다. 같은 세션을 대화 기록(채팅)으로 볼지, 에이전트의 원래 터미널 화면으로 볼지 고릅니다. 에이전트 바꾸기와 상관이 없어서 이번 그림에서는 뺐습니다. 실제 앱에서는 세션 머리 오른쪽에 그대로 있습니다.

업계 표준

  • 출처VS Code: 입력창의 Session Target 드롭다운에서 Copilot, Claude, Codex, Cloud로 넘깁니다. "대화 기록과 맥락을 넘긴다"고 하고, 도구·권한·모델이 바뀔 수 있다고 경고합니다. 모델 선택은 harness를 바꾸지 않는다고 따로 적혀 있습니다. (VS Code agent harnesses)
  • 출처Claude 앱: 대화 중 언제든 모델을 바꾸고, 바뀐 모델은 다음 답부터 적용됩니다. (Claude 도움말)
  • 출처Cursor: 대화 중 모델을 바꿔도 맥락이 유지됩니다(포럼 직원 답변). CLI에서 메시지 앞에 "&"를 붙이면 클라우드 에이전트로 넘깁니다. 다른 회사 CLI로는 못 넘깁니다. (Cursor 포럼 · Cursor CLI 변경 기록)
  • 출처Zed: 스레드 하나에 에이전트 하나. 새 스레드 메뉴에서 고르고, 기존 스레드를 다른 에이전트로 바꾸는 방법은 문서에 없습니다. (Zed external agents)
  • 출처Conductor: 모델 선택기 하나에 Claude Code, Codex, Cursor, OpenCode 모델이 함께 있습니다. 에이전트끼리는 대화가 아니라 같은 worktree(파일·git)를 나눠 씁니다. (Conductor + Codex)
  • 출처Warp: 다른 에이전트로 넘기지 않고, /fork로 맥락을 이어받은 새 대화를 만듭니다. (Warp forking)
  • 출처Superset(문서 주소가 Paradev로 옮겨짐): 전환 버튼이 없고, 다른 에이전트는 다른 워크스페이스에서 띄웁니다. (Superset agents)
  • 출처T3 Code: 제공자 어댑터마다 모델 변경을 "세션 안 / 세션 재시작 / 불가" 중 하나로 정합니다(비공식 문서 사본). 기억스레드 안에서 Claude↔Codex를 바꾸는 화면은 확인하지 못했습니다. (T3 Code providers)
  • 기억ChatGPT: 대화 중 모델을 바꾸고, 답 하나를 다른 모델로 다시 생성할 수 있습니다. Windsurf: 입력창 아래 모델 드롭다운.

정리: 모델 선택은 어디서나 입력창에 있습니다. 다른 에이전트로 넘기기를 문서화한 곳은 VS Code뿐이고, 그것도 입력창의 같은 드롭다운입니다. 머리 버튼(옛 A)은 업계에 없습니다.

왜

  • 사용자는 "어느 에이전트"보다 "어느 모델"로 생각합니다. 모델과 에이전트를 한 선택기에 두면 고르는 곳이 하나뿐입니다(Conductor, VS Code와 같음).
  • 1차에서 B를 뺀 이유는 "가벼운 모델 선택 옆에 무거운 동작(새 세션)이 있어 잘못 누르기 쉽다"였습니다. 고르기만 해서는 아무것도 시작하지 않고 Enter 때 시작하게 하면, 잘못 골라도 Esc 한 번으로 끝납니다.

04후속 질문: 주력 에이전트가 Claude도 Codex도 아니라면

무엇을 정하나요: Gemini CLI, opencode, Aider, 다른 ACP 에이전트를 주로 쓰는 사람에게 첫 실행, 기본 에이전트, 문제 카드가 어떻게 동작할지. 04 B(빈 창이 곧 첫 실행 + 한 줄 띠)는 그대로 두고 내용만 정합니다.

업계 표준

  • 출처Zed: ACP 레지스트리에서 에이전트를 설치하고(Add Agent › Install from Registry), 직접 추가는 settings의 agent_servers(command, args, env)를 엽니다. 로그인은 스레드 안에서 그 에이전트의 로그인 명령을 터미널로 띄웁니다. (Zed external agents)
  • 출처ACP 레지스트리: JSON 목록에 46개(Gemini CLI, OpenCode, goose, Amp, Cline, Qwen 등). 인증을 지원하는 에이전트만 올라갑니다. Aider는 목록에 없었습니다. (ACP registry)
  • 출처Superset(현 Paradev): 내장 22개 에이전트를 자동으로 감지하고 켜고 끕니다. "Custom agent…"로 아무 CLI나 추가하되, 상태·재개 연동은 없습니다. 에이전트가 없을 때 띄우는 카드는 없습니다. (Paradev agents · agent integration)
  • 출처Warp: 패널에서 알려진 CLI 에이전트(Claude Code, Codex, Gemini CLI, OpenCode, Amp 등)를 실행하면 알아보고 도구 막대를 붙입니다. 기본 에이전트 설정은 없습니다. (Warp CLI agents)
  • 출처이 Macherdr 0.9.5: 화면과 프로세스로 에이전트를 감지하고, 모르는 에이전트는 "그냥 터미널"로 보입니다. herdr agent start --kind는 정해진 24종만 받고, 기본 에이전트는 없습니다. (herdr agents)
  • 출처cmux: 첫 실행은 터미널 하나와 워크스페이스 하나이고, 에이전트 설정 단계가 없습니다. 연동되는 17종 밖의 에이전트는 일반 터미널로 다시 엽니다. (cmux session restore)
  • 기억Conductor: 문서에는 Claude Code, Codex, Cursor, OpenCode만 나오고, 첫 실행 화면은 확인하지 못했습니다.

정리: 첫 실행에 "주력 에이전트"를 묻는 도구는 없습니다. 감지된 것을 보여 주고, 기본값은 마지막에 쓴 것입니다(Zed). 모르는 에이전트는 어디서나 일반 터미널로 돌아갑니다. 없는 에이전트나 로그아웃을 카드로 알려 주는 도구는 드뭅니다. GUI가 메울 수 있는 빈자리입니다.

왜

  • "주력이 무엇이냐"를 묻지 않아도, 처음 시작한 세션의 에이전트가 곧 기본값이 됩니다(V2-11 기본값 기억). 질문 하나가 줄어듭니다.
  • ACP 에이전트는 V2-4 승인 시트를 반드시 거쳐야 하므로, 첫 실행의 "쓰기" 버튼이 그 시트를 열면 단계가 따로 늘지 않습니다.

  1. 찾기: 로그인 셸 PATH에서 claude, codex와 Nunchiro가 아는 ACP 에이전트 목록(레지스트리 이름에서 고른 짧은 목록, 앱에 포함)을 찾습니다. 인터넷에서 받아 오지 않고, 설치하지도 않습니다.
  2. ACP 에이전트를 찾으면: "Gemini 쓰기(명령 확인)…"가 V2-4 승인 시트를 열고, 정확한 명령을 보여 준 뒤 승인하면 바로 첫 세션을 엽니다.
  3. ACP가 아닌 CLI(예: Aider): "터미널로만" 표시합니다. 일반 셸 세션에서 그 명령을 실행하고, 채팅 보기와 대기 감지는 없다고 그 자리에서 한 줄로 알립니다. Superset의 Custom agent와 같은 수준입니다.
  4. 아무것도 없으면: claude, codex 설치 페이지와 "다른 에이전트 추가…"(agents.toml)를 보여 줍니다.
  5. 기본 에이전트: 묻지 않습니다. 새 세션 시트는 프로젝트별로 마지막에 쓴 에이전트를 미리 고르고, 처음 보는 프로젝트는 전체에서 마지막에 쓴 것을 고릅니다. 설정 › 에이전트에서 보이고 바꿀 수 있습니다.
  6. 문제 카드(같은 틀): 설치 안 됨 → 설치 페이지; 로그인 필요(ACP authenticate) → 그 에이전트의 로그인 명령을 보이는 터미널 탭에서 실행(키는 저장 안 함); 실행 실패나 ACP 응답 없음 → "명령 고치기"(agents.toml 항목) + 자세히(stderr); 명령이 바뀜 → 카드가 아니라 승인 시트; API 키 없는 Claude ACP → V2-4대로 거부하고 이유를 한 줄로 보여 줌.

08Spaces: 정말 정했나, herdr식으로 가기로 하지 않았나

무엇을 정하나요: 프로젝트가 많을 때 무엇으로 정리할지. Spaces(이름 붙인 프로젝트 묶음)를 유지할지, 빼고 다른 방법을 쓸지.

사실 관계
  • needs 22 "Spaces"는 the owner의 요청이 아니라 에이전트 제안이었습니다(JCodesMore/orca 포크에서 가져옴, 2026-10-24).
  • needs 73(2026-10-26)에서 v2 범위를 승인하실 때, 보류 중이던 제안(22, 58)이 한꺼번에 v2로 들어갔습니다. Spaces만 따로 고르신 적은 없습니다.
  • needs 33에서 "워크스페이스로 나누는 것 자체가 더 헷갈린다"고 하셔서 워크스페이스와 이름 붙인 모드를 뺐습니다.
  • needs 34, 36에서 herdr처럼 main과 worktree를 확실히 나누는 트리(C안)를 고르셨습니다. 즉 "herdr식"으로 정한 것은 트리 모양이고, 그 위에 묶음 단계를 두자고 정한 적은 없습니다.
  • 이 Macherdr 자체(0.9.5, herdr --help, herdr workspace --help, 설정 파일 읽기만): 단위는 세션 › 워크스페이스 › 탭 › 패널입니다. workspace create --cwd --label로 폴더 하나에 워크스페이스 하나를 만들고, workspace_picker(prefix+w)와 이전/다음 워크스페이스 키로 오갑니다. The owner 설정에는 agent_panel_sort = "priority"와 워크스페이스 위아래 이동 키가 있습니다. 공식 문서는 워크스페이스를 "맨 위 프로젝트 단위"라 부르고, 그 위의 이름 붙인 세션은 따로 노는 공간이며 "워크스페이스를 먼저 쓰라"고 합니다(herdr concepts). herdr의 워크스페이스 = Nunchiro 트리의 프로젝트이고, herdr에는 프로젝트 묶음 단계가 없습니다.

업계 표준

  • 출처Orca(stablyai): 사이드바가 프로젝트별로 worktree를 묶고, 고정, 끌어서 순서 바꾸기, 필터 칸, 필터 메뉴(머신, 프로젝트, 잠든 것 숨기기)가 있습니다. Spaces 개념은 없습니다. (Orca worktrees)
  • 출처Conductor: 프로젝트 › 워크스페이스. 변경 기록에 "Pinned Workspaces", "Search Workspaces", "Group workspaces by repo"가 차례로 들어갔고, 저장소 위 단계는 없습니다. (Conductor changelog)
  • 출처Superset(현 Paradev): 프로젝트 아래 워크스페이스, 프로젝트를 넘나드는 Pinned 구역, 프로젝트별 "사이드바에서 숨기기", 정렬과 필터. (Paradev workspaces)
  • 출처cmux: 세로 탭 사이드바의 평평한 워크스페이스 목록뿐입니다. ⌘1–8로 전환, ⌘⇧U로 가장 최근 안 읽은 알림으로 갑니다. (cmux README)
  • 출처tmux: 서버 › 세션 › 창 › 패널, choose-tree에 필터. Zellij: 세션 관리자 창 하나, 묶음 없음. (tmux man · Zellij session manager)
  • 출처VS Code: 다중 루트 워크스페이스는 선택 사항이고, 없어도 씁니다. 기억많은 프로젝트는 Open Recent나 Project Manager 확장(태그, 즐겨찾기)으로 다룹니다. (VS Code workspaces)
  • 출처Arc: Spaces가 맨 위 단위이고 Space마다 고정 탭과 프로필이 있습니다(제3자 안내 기준). Dia는 Spaces 없이 나왔다가 사용자 불만을 들었습니다. 다만 브라우저 탭 이야기이고, 저장소 오가기와는 다릅니다. (Arc Spaces 안내 · TidBITS)

정리: 에이전트 터미널 도구(Orca, Conductor, Superset, cmux, herdr) 중 이름 붙인 Spaces를 둔 곳은 없습니다. 모두 프로젝트를 맨 위에 두고, 프로젝트가 많아져 불편해지면 고정, 필터/검색, 숨기기를 하나씩 더했습니다.

왜

  • Spaces는 needs 33에서 빼신 "나누기"를 다시 들여옵니다. 다른 Space의 대기를 놓치지 않게 하려면 알약마다 숫자가 필요해, 화면이 복잡해집니다.
  • 지금 트리가 이미 쓰는 "접기" 말(worktree N 한 줄)을 프로젝트에도 쓰면 새 개념 없이 긴 목록이 짧아집니다. 대기, 작업 중, 실패가 있는 프로젝트는 절대 접히지 않아 needs 26을 지킵니다.

09맡기고 떠나기: 알림, 돌아왔을 때 요약, 검토함

무엇을 정하나요: 에이전트에게 일을 맡기고 자리를 떴을 때 무엇을 휴대폰으로 알리고, 돌아왔을 때 무엇을 어디서 보여 줄지. needs 26(대기가 작업 위에 뜨거나 화면을 밀지 않음)은 지킵니다.

업계 표준
