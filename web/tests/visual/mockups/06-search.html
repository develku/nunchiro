06 · Search across sessions and transcripts (V2-7)

V2-7 (needs 69). Full-text search over the chat events of every session Nunchiro started, running or closed, with project, agent and date filters. A hit opens that chat at the event; a closed session opens read-only with Resume. No index first: results stream in while transcripts are scanned, so every option shows progress. Only Nunchiro’s own sessions are searched (open question 4, recommended).

Recommendation: Option A, with B’s palette scope as the quick path to the same results (spec V2-7 asks for both). A keeps the hit list beside the chat so you can walk hits without reopening anything, and it reuses the existing Search panel instead of adding a tab type. Main risk: the tree is hidden while searching; waiting stays visible through tab dots, AGENTS dots and the menu bar, and esc brings the tree back.

Interaction modelTransient modal: query → pick → jump.

RationaleZero new places: ⌘K then Tab to Sessions. The preview shows the hit in context before you jump, so most look-ups end without opening a tab. Fastest for keyboard users.

Trade-offModal: the palette covers the window, so you can’t read a hit and type in the composer at once; to check the next hit you reopen it. Filters are terse tokens, less discoverable.

Accessibilityrole=dialog with combobox + listbox + a preview region labelled by the selected hit; Tab cycles scopes and is announced; focus returns to the prior element on esc; scrim is decorative.

A tab like Settings: stays open while you jump to hits and come back; ⌘⇧F opens it with the selection.

Interaction modelDocument-like: results are a place you keep and return to.

RationaleRoom for long snippets, all filters visible as checkboxes, and the results survive while you visit hits (like a VS Code search editor). Best for “what did we decide about X last week” across many sessions.

Trade-offHeaviest: another tab type, and jumping to a hit switches tabs, so you bounce between the results tab and the session. Takes the composer away while it is in front.

AccessibilityFilters are real checkboxes and radios in labelled groups; results are a table-like list with row headings (session) for screen readers; live count; each row’s buttons are named “Open core-serve at 14:03”.
