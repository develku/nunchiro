점수표 p06(에이전트 호환)은 지금 45점입니다. 깊이(줄)는 90인데 넓이가 0입니다. 넓이는 "점수 매기는 날 진짜 한 턴을 끝낸 에이전트 종류의 수"이고, 가장 앞선 Orca는 45가지를 목록에 둡니다. 아래는 종류를 늘리는 세 가지 안과, 설치·로그인이 창에서 어떻게 보이는지, 진짜 턴을 어떻게 확인하는지입니다.

추천: B, 두 번에 나눠 만들기
  1. 길은 ACP 하나입니다. Claude와 Codex 말고는 모두 ACP(에이전트 표준 연결)로 붙입니다. ACP는 "보냄, 답 읽음, 턴 끝"이 규약에 있어서 진짜 턴을 정확히 확인할 수 있습니다. 화면을 읽어야 하는 터미널 전용 도구는 세지 않습니다.
  2. 먼저 "진짜 한 턴"을 만듭니다. 설정의 에이전트 줄에 Send a test message가 생깁니다. 짧은 문장 하나를 보내고 답과 턴 끝을 확인합니다. 다른 앱은 여기까지 하지 않습니다(연결만 확인).
  3. 다음에 목록을 늘립니다. 9가지에서 18가지쯤으로. 줄마다 설치 명령, 로그인 방법, 비용 한 줄이 붙습니다.
  4. 설치는 보이는 터미널 탭에서. Nunchiro가 명령을 적어 두고, Return은 사용자가 누릅니다.
  5. 목표는 12가지입니다. 9가지로는 80에 겨우 닿거나 못 닿습니다(10번).

A. 목록만 늘리기

known.toml에 줄을 더합니다(Copilot, Kiro, Kilo, Mistral Vibe, Cline 등). 화면과 흐름은 그대로입니다. 진짜 턴은 점수 매기는 날 사용자가 스크립트로 한 종류씩 돌립니다.

얻는 것
  • 가장 작습니다. 데이터 파일과 타일 몇 줄.
  • 이미 깔고 로그인한 사람에게는 충분합니다.
약점
  • 새 사용자는 "무엇을 깔고, 어디서 로그인하고, 돈이 드는지"를 여전히 밖에서 찾아야 합니다.
  • 앱은 그 에이전트가 정말 답하는지 모릅니다. Passed는 연결됐다는 뜻일 뿐입니다.
  • 12가지를 손으로 돌리면 채점 때마다 한 시간쯤 듭니다.

규칙
  • 설치: 공급사가 npm이나 brew 방식을 문서에 두면 그것을 씁니다. curl … | bash뿐이면 전체를 그대로 보여 줍니다. Nunchiro는 명령을 적기만 하고 실행은 사용자가 합니다. 명령과 출처 주소는 앱에 들어 있는 목록에서 옵니다.
  • 승인: 지금과 같습니다. 정확한 명령과 변수 이름을 보여 주고, 보여 준 것과 저장된 것이 같을 때만 승인됩니다. 설치된 경로가 채워져 있어서 대부분 버튼 한 번입니다.
  • 로그인: 지금 있는 두 길입니다. 에이전트가 ACP로 알려 준 방법(브라우저), 또는 터미널 탭에서 그 도구의 로그인 명령. Nunchiro는 토큰을 읽거나 저장하지 않습니다.
  • 시험 메시지: 정해진 한 문장. 가둔 빈 폴더에서, 최대 60초, 에이전트가 권한을 물으면 거절합니다. 사용자의 프로젝트는 건드리지 않습니다.
  • 칩: Not tried → Answered {when}. 에이전트 버전이 바뀌면 Not tried on {version}으로 돌아갑니다. 막지는 않습니다.
  • 저절로 보내지 않습니다. 시험 메시지는 사용자가 누를 때만 갑니다. 남의 한도를 몰래 쓰지 않기 위해서입니다.
  • 비용 줄: 확인한 날짜와 공급사 가격 쪽 링크가 붙습니다. 가격은 자주 바뀌므로 숫자는 링크가 기준입니다.
Claude와 Codex
  • 같은 칩을 씁니다. 이 둘은 터미널에서 돌므로, 시험은 지금의 채팅 확인(메시지가 들어가고 턴이 끝남)을 한 번 돌리는 것입니다.

5

사용자가 내는 것

만드는 일은 에이전트가 하지만, 아래는 사용자의 계정과 손이 필요합니다. 에이전트는 로그인하지 않고, 계정을 만들지 않습니다.

한 번채점 때마다
설치7가지를 새로 깝니다 (Copilot, Kiro, Kilo, Mistral Vibe, Cursor, Cline, goose). npm 3, brew 1, curl 설치 스크립트 3. 10~15분.없음. 에이전트가 스스로 업데이트하면 버전만 바뀝니다.
로그인브라우저 로그인 7~8번: GitHub, AWS Builder ID(또는 Google/GitHub), Kilo, Mistral, Cursor, Cline, OpenCode 연결, 그리고 Hermes·goose의 모델 제공자. 새 계정이 4~5개 생깁니다(Kilo, Mistral, Cursor, Cline, AWS Builder ID).만료된 로그인만 다시.
구독새로 내는 돈 0원이 목표입니다. 무료 범위가 위 표대로일 때.짧은 턴 12번. Claude·Codex는 지금 요금제에서, 나머지는 무료 한도에서.
위험무료 범위는 자주 줄어듭니다. 올해만 Gemini CLI(6월), Qwen(4월), Amp(5월)가 줄었습니다. 그래서 12가지에 예비를 둡니다. 9~10번이 안 되면 유료 하나(예: Copilot Pro $10/월)가 가장 싼 메움입니다.
개인 정보각 서비스의 약관에 사용자가 동의하는 일입니다. 시험 메시지는 빈 폴더에서 한 문장이라 코드가 나가지 않습니다. 그 뒤 실제로 쓰는 세션은 그 서비스로 코드를 보냅니다.

진짜 턴을 어떻게 확인하나

같은 확인을 두 곳에서 씁니다. 창에서는 사용자가 줄마다 누르고, 채점 때는 스크립트가 깔려 있는 종류를 모두 돌려 기록 파일을 남깁니다.

  • 가짜 에이전트는 스크립트 자체의 시험에만 쓰고 수에 넣지 않습니다. 기록에 실행 파일 경로와 버전이 남습니다.
  • 스크립트는 사용자의 ~/.nunchiro와 설치된 앱을 건드리지 않습니다. 시험용 홈에 코어를 따로 띄웁니다. 에이전트는 자기 로그인을 그대로 씁니다.
  • 깔려 있지 않거나 로그인 안 된 종류는 SKIP으로 적고 0으로 셉니다.
  • 점수표의 "Real agent turns" 단계가 이 명령 하나가 됩니다. 기준은 같고, 손으로 하던 것을 기록으로 남길 뿐입니다.
다른 앱은
  • T3 Code, Paseo, Orca, Superset 모두 버전과 연결(initialize, session/new)까지만 봅니다. 진짜 메시지를 보내 확인하는 앱은 찾지 못했습니다. 이것이 Nunchiro의 차이입니다: "연결됨"이 아니라 "답함".
7

C. B + 온라인 ACP 목록에서 고르기 (지금은 아님)

ACP 공식 목록(오늘 46가지)을 앱에서 읽고, 고르면 Nunchiro가 실행 파일을 받아 깝니다. T3 Code와 Orca가 이렇게 합니다.

얻는 것
  • 목록이 저절로 늘어납니다. 새 에이전트가 나오면 앱 업데이트 없이 보입니다.
  • 설치가 버튼 하나입니다.

사용자가 답할 질문

각 질문 아래가 추천입니다. 만들기는 승인 뒤에 시작합니다.

1. A, B, C 가운데 어느 것입니까?추천: B. PR 1(진짜 한 턴과 채점 스크립트)을 먼저, PR 2(목록, 네 단계, 비용 줄)를 다음에. C는 "목록은 온라인에서 받지 않는다"를 바꾸는 일이라 따로 정합니다.
2. 몇 가지를 목표로 합니까?추천: 12가지(4번 표). 9가지는 VC1까지 되어야 80.07이고 한 종류만 실패해도 내려갑니다. 다른 답: 9가지 + VC1을 먼저.
3. 설치 7가지와 브라우저 로그인 7~8번, 새 계정 4~5개를 사용자가 해 주실 수 있습니까?추천: 예, PR 2가 들어온 뒤 한 번에(15~30분). 창의 줄을 따라 누르면 되고, 그 자체가 흐름의 시험입니다. 에이전트는 로그인하지 않습니다. 새 계정이 싫은 서비스는 빼고 예비에서 고릅니다.
4. 무료 범위가 모자라면 유료 하나를 씁니까?추천: 지금은 아니오. 먼저 무료로 되는 수를 세어 봅니다. 11가지에서 멈추면 그때 가장 싼 것(예: Copilot Pro $10/월)을 여쭙니다.
5. 설치 명령을 Nunchiro가 직접 실행해도 됩니까?추천: 아니오. 터미널 탭에 적어 두고 Return은 사용자가 누릅니다. 인터넷에서 받은 설치 스크립트를 앱이 조용히 돌리지 않습니다. 다른 답: emdash처럼 버튼이 바로 실행.
6. 시험 메시지를 버전이 바뀔 때 저절로 다시 보냅니까?추천: 아니오. 칩만 Not tried on {version}으로 바뀝니다. 사용자의 한도를 몰래 쓰지 않습니다.
