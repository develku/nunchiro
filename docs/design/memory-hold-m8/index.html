메모리가 부족해 새 세션이 보류됐을 때, 창에서 한 번에 넘기거나 기다리게 합니다

PR #44부터 macOS가 메모리 압박을 알리면 새 세션이 시작되지 않습니다. 창에는 넘길 방법이 없어서 터미널 명령을 안내하는 긴 문장만 나옵니다. 아래는 창에 버튼을 넣는 안 세 가지입니다. 세 안 모두 메모리가 정상일 때는 화면이 지금과 같습니다.

추천: B, 두 번에 나눠 만들기
  1. 먼저 A를 냅니다. 시작이 안 됐다는 줄에 Start anyway 버튼이 붙습니다. 창 쪽 일이 대부분이라 작습니다.
  2. 다음에 기다림을 붙입니다. 보류된 시작은 없어지지 않고 기다렸다가 메모리가 풀리면 하나씩 시작됩니다. 기다리는 동안에만 상태 막대에 한 줄이 생깁니다.
  3. 에이전트, 리드, 예약이 낸 시작도 같은 줄에 보입니다. 그쪽은 넘길 수 없고, 사용자만 Start anyway 또는 Cancel을 누를 수 있습니다.
  4. 트리는 바꾸지 않습니다. 압박이 높아도 보류된 시작이 없으면 아무것도 보이지 않습니다.

A. 버튼만: 시작 안 된 줄에 Start anyway

문장을 줄이고 버튼을 붙입니다. 누르면 같은 시작을 그대로 다시 보내 시작합니다. 기다리는 것은 없습니다. 에이전트나 리드의 시작이 보류되면 지금처럼 그쪽만 문장을 받고, 창에는 아무것도 뜨지 않습니다.

보이는 것
  • 줄은 지금의 실패 줄과 같은 자리, 같은 글씨입니다. 버튼은 Undo 줄의 버튼과 같은 연한 버튼입니다. 주황(내 차례)이나 빨강은 쓰지 않습니다.
  • 버튼에 마우스를 올리면 결과 한 줄이 뜹니다. 다른 앱도 "anyway" 버튼 옆에 결과를 한 줄 적습니다.
  • ×는 줄만 닫습니다. 시작은 일어나지 않습니다.
  • Terminal은 보류되지 않으므로 이 줄이 나오지 않습니다.
약점
  • 리드가 팀원을 못 열었을 때 사용자는 모릅니다. 리드는 "나중에 다시 해 보라"는 문장만 받고, 다시 할지는 리드에게 달려 있습니다.
  • warning은 세션이 여럿일 때 오래 이어질 수 있어서, 그동안 에이전트의 시작은 계속 거절됩니다.

규칙
  • 언제 시작되나: 기다리는 것이 있을 때만 10초마다 압박을 읽습니다. 세 번 이어서 괜찮으면 하나를 시작하고, 다음 것은 30초 뒤에 다시 읽고 시작합니다. 한꺼번에 시작하면 압박이 다시 오르기 때문입니다.
  • 얼마나 기다리나: 30분. 지나면 목록에서 빠지고 한 줄이 남습니다. 예약은 기록에 skipped: low memory로 남습니다.
  • 누가 넘기나: 사용자만. 에이전트, 리드, 예약은 넘길 수 없고, 목록에서 사용자가 대신 Start anyway나 Cancel을 누릅니다.
  • 낸 쪽은 무엇을 받나: "기다리는 중이고 저절로 시작되니 다시 시작하지 말라"는 문장. 시작되거나 취소되면 메시지 한 줄을 받습니다(아래).
  • 기다리지 않는 것: 시작한 뒤 바로 할 일이 딸린 내 시작(사이드 챗, 분기, 뒤에서 실행, 다른 계정에서 이어 하기)은 A처럼 버튼만 나옵니다. 쓰던 글은 입력칸에 그대로 남습니다.
  • 코어가 다시 시작되면: 기다리던 시작은 없어집니다. 저장하지 않습니다. 예약은 다음 시각에 다시 돕니다.
